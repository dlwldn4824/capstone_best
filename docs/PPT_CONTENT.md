# 발표 자료 원고 — 고칠 것과 더할 것

[`PPT_REVIEW.md`](PPT_REVIEW.md) 가 "무엇이 문제인가"라면, 이 문서는 **슬라이드에 그대로 올릴 글**이다.
숫자는 전부 [README "숫자로 보는 결과"](../README.md) 와 `outputs/tables/` 에서 왔다.

각 슬라이드는 다음 형식이다.

> **제목** / **부제** / **본문** (표·도식) / **한 줄** (하단 강조 문장) / **말할 것** (발표 멘트) / **각주** (출처)

---

# 1부. 수정 방향

## 1.1 지금 덱의 구조적 문제

발표가 이렇게 흐른다.

```
문제 제기(3~5) → 하드웨어 3안(6~7) → 선행연구(8~10) → 재현(11~14) → 다음 과제(15)
                  ^^^^^^^^^^^^^^^
                  근거가 아직 안 나왔는데 해법이 먼저 나온다
```

**6·7장이 8~14장보다 앞에 있다.** 아직 아무것도 검증하지 않은 상태에서
"EDA 를 쓰자, 땀 패치를 붙이자, 심부 체온을 재자"가 나온다. 심사에서
**"왜 그 세 개인가"** 를 물으면 답할 슬라이드가 덱 안에 없다.

그 답이 실제로는 있다. **WESAD HRV 판정**이다. 그런데 그게 덱에 없다.

## 1.2 고치는 방법 — 순서를 뒤집는다

```
문제 제기 → 기저율(왜 문턱으로 못 푸나) → 질문 재정의 → 선행연구
  → 재현 → 검증 결과 6가지 → HRV 판정 → 그래서 하드웨어는 이 방향
                              ^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^
                              근거          결론
```

바꾸는 건 **슬라이드 두 장을 뒤로 옮기고, 그 앞에 근거를 채우는 것**이다.
6·7장을 버리는 게 아니라 **결론의 자리로 옮긴다.**

## 1.3 세 가지 원칙

| 원칙 | 왜 |
| --- | --- |
| **불리한 수치를 우리가 먼저 말한다** | 오류의 9.5%, 우연 수준 미달, 규칙이 성능을 못 올림 — 심사자가 찾아내면 실점, 우리가 먼저 내면 득점 |
| **숫자 옆에 항상 짝을 붙인다** | 경보율 옆에 탐지율, 정밀도 옆에 우연 정밀도. 하나만 쓰면 그게 곧 과장이다 |
| **한 슬라이드 = 한 문장** | 하단 "한 줄"만 읽어도 논지가 이어지게 |

## 1.4 표기 통일 (덱 전체)

| 항목 | 통일안 |
| --- | --- |
| 피험자 수 | `36명 모집 · 34명 분석` (f07·f13 착용 불량, 원 논문과 동일) |
| 구간 수 | 재현 슬라이드만 `482구간(논문 정의)`, 그 외 전부 `1,251윈도(60초/30초 이동)` |
| 성능 지표 | **Macro F1** 로 통일 (정확도와 섞지 않는다) |
| 분할 표기 | 수치 옆에 항상 `무작위` 또는 `피험자 분리` 를 붙인다 |
| 데이터 이름 | `Hongn(실험실)` · `Nurse(실환경)` · `WESAD(동시측정)` |

# 2부. 기존 슬라이드 수정안

## 2장 — 목적 · 페르소나 (비어 있음)

> **제목** 무엇을 확인하려 했나
> **부제** 캡스톤 진행 동기와 대상 사용자

**본문 — 왼쪽: 동기**

건강 웨어러블은 "오늘 컨디션이 나쁘다"고 알린다.
그런데 **어제 술을 마셔서 그런 것**이면, 기기는 그걸 모른 채 매일 빨간불을 켠다.
그러다 **진짜 아픈 날에도 무시하게 된다.**

**본문 — 오른쪽: 페르소나**

| | |
| --- | --- |
| 누구 | 웨어러블을 매일 차는 20–40대 직장인 |
| 생활 | 주 3–4회 운동 · 잦은 야근 · 주 1–2회 음주 |
| 겪는 일 | 이상 알림이 자주 뜨는데, 대부분 **본인은 이유를 안다** |
| 그래서 | 알림을 신뢰하지 않게 되고, 결국 **꺼버린다** |

> **한 줄** 이 사람에게 필요한 건 알림을 줄이는 게 아니라, **이유가 있는 날을 걷어내는 것**이다.

**말할 것** — "설명이 되는 날을 기기가 모른다는 게 문제의 출발점입니다.
그리고 그 설명은 사용자 본인이 이미 갖고 있습니다."

| 수면 부족 | 부교감 활동 감소 → 감염 시와 같은 방향 |
| 심리적 스트레스 | Oka 2015 (4장과 동일 출처, 재인용 표기) |
| 과도한 음주 | **출처 필수** — 현재 수치만 있고 논문명이 없다 |

> ⚠ [`LITERATURE_VERIFICATION.md`](LITERATURE_VERIFICATION.md) 에 아직 검증 안 된 인용이 있다.
> **발표 전에 이 4개 출처를 전부 원문 대조할 것.** 수치를 못 찾으면 수치를 뺀다.

> **제목** 알림 횟수가 문제가 아니다

| --- | --- |
| 운동 · 음주 · 늦게 잔 날 · 일이 몰린 날 | 주 3–4회 → **월 15회 안팎** |
| 실제로 감염되는 것 | 성인 연 2–3회 → **월 0.2회** |

**본문 — 오른쪽: 갈림길**

| | |
| --- | --- |
| 문턱을 **높이면** | 알림은 조용해지지만 초기 신호를 놓친다. Mishra 의 0.66회/인·월이 작아 보이는 건 이쪽으로 맞췄기 때문이다 |

> **한 줄** 문턱을 어디에 두든 손해다. **그 15회를 설명해서 걷어내야 풀린다.**

**말할 것** — "앞 장에서 0.66회라는 숫자를 봤습니다. 한 달에 한 번이면 참을 만하죠.
그래서 문제가 아니라고 생각하기 쉽습니다. 그런데 그건 문턱을 높게 잡았기 때문이고,
초기에 잡는 게 이 기술의 존재 이유입니다. 낮추면 이쪽 15회가 쏟아집니다."

**각주** — 빈도는 일반 성인 기준 추정치. 감염 빈도는 성인 연 2–3회 상기도 감염 기준.

## S7. 그래서 질문을 바꿨다 `A순위`

> **제목** 감염을 찾지 말고, 설명되는 것을 걷어낸다
> **부제** 판정 흐름

**본문 — 흐름도** (README 의 mermaid 를 그림으로. 좌→우 또는 위→아래)

```
이 사람의 평소와 다른가?
   ├ 같다 ─────────────────────→ 아무 말도 안 함
   └ 다르다
        ├ 운동으로 설명되나? (가속도) ──→ 설명됨
        ├ 스트레스로 설명되나? (피부전도) ──→ 설명됨
        ├ 술·잠 부족인가? (사용자에게 물어봄) ──→ 설명됨
        └ 짚이는 것 없음 → 설명되지 않는 변화
                              └ 며칠 지속되나?
                                   ├ 하루뿐 → 더 지켜봄
                                   └ 사흘 연속 → 알림
```

**본문 — 오른쪽 박스**

**분류기는 "모른다"고 말할 수 없다.** 배운 것 중에 반드시 하나를 골라야 한다.
그런데 진짜 몸에 이상이 생기면 그건 우리가 가르쳐준 적 없는 상황이다.
**모른다고 답하는 게 정답인 상황**이다.

> **한 줄** 우리가 만드는 건 감염 탐지기가 아니라 **설명 필터**다.

**말할 것** — "여기서 문제를 뒤집었습니다. 감염을 찾아내려 하지 않고,
설명이 붙는 날을 걷어냅니다. 남는 게 볼 가치가 있는 날입니다."

## S9. 검증 데이터 3종과 연결 구조 `신규`

> **제목** 공개 데이터 세 개로 직접 돌렸다
> **부제** 각 데이터가 앞 데이터에서 생긴 질문에 답한다

**본문 — 도식**

```
Hongn 2025 (실험실 · 34명)
   └→ 오분류의 84.6%가 휴식↔스트레스였다
        └→ 질문을 다시 잡음: "평소와 다른가?"
             └→ Nurse Stress 2022 (실제 병원 · 1,241시간)
                  └→ 피부전도는 통하고 HRV는 안 통한다
                       └→ 생리적 사실인가, 손목의 한계인가?
                            └→ WESAD 2018 (가슴 ECG + 손목 동시)
                                 └→ 손목의 한계다
```

**본문 — 표**

| 데이터 | 무엇 | 규모 |
| --- | --- | --- |
| **Hongn 2025** | 실험실 · 자전거 운동과 암산 과제 | 34명 / **1,251 윈도** |
| **Nurse Stress 2022** | 실제 병원에서 근무하는 간호사 | 15명 / **1,241시간** (148,929 윈도) |
| **WESAD 2018** | 가슴 ECG 와 손목을 **동시에** 측정 | 15명 / **877 윈도** |

> **한 줄** 데이터를 늘린 게 아니라, **앞 결과가 만든 질문을 따라간 것**이다.

**말할 것** — "세 데이터를 나열한 게 아닙니다. 첫 번째에서 나온 질문에 답하려고
두 번째를 가져왔고, 거기서 또 갈리지 않는 게 생겨서 세 번째를 가져왔습니다."

## S11. 분할을 바꾸면 −0.09 `A순위`

> **제목** 논문 수치를 그대로 쓸 수 없다
> **부제** 같은 모델 · 같은 특징 · 분할 방식만 바꿨다

**본문 — 표** (Macro F1)

| 과제 | 무작위 분할 | 피험자 분리 | 차이 |
| --- | --- | --- | --- |
| 휴식 / 스트레스 | 0.896 | 0.761 | **−0.136** |
| 유산소 / 스프린트 | 0.980 | 0.980 | −0.000 |
| 3분류 | 0.923 | 0.809 | **−0.113** |
| 4분류 | 0.916 | 0.819 | **−0.097** |

**본문 — 오른쪽 박스**

**떨어지지 않은 건 유산소/스프린트 하나뿐이다.**
움직임의 세기는 남이 봐도 그대로 읽히기 때문이다.
반대로 **사람 안쪽 상태를 묻는 과제일수록 많이 떨어진다.**

LOSO(한 명씩 빼기)도 0.832 로 피험자 분리와 같은 수준이다.
→ **무작위 분할만 유독 높다. 누수가 맞다.**

> **한 줄** 같은 사람이 학습과 평가에 같이 들어가면 성적이 부풀려진다.

**말할 것** — "논문이 틀렸다는 게 아닙니다. 인용할 때 조건을 같이 써야 한다는 겁니다.

## S18. HRV 는 손목으로 못 잰다 `A순위` ★ 가장 견고한 발견

> **제목** HRV 는 반응한다. 손목으로 잴 수 없을 뿐이다
> **부제** WESAD · 같은 사람 · 같은 시각 · 가슴 ECG(700 Hz)와 손목 PPG(64 Hz) 동시 기록

**본문 — 설계 한 줄**

두 신호에 **같은 HRV 함수**를 적용했다. 계산 방식이 다르면 비교가 무의미하다.
차이가 나면 그건 순수하게 **신호 품질 차이**다.

**본문 — 표 1: 갈린다**

| | 가슴 ECG | 손목 PPG |
| --- | --- | --- |
| RMSSD | 48.6 → 32.0 · **−13.0 ms (−27%)** · **10/15명** | 154.0 → 133.2 · **+5.0 ms (방향 반대)** · 7/15 |

**본문 — 표 2: 결정적 대조 (같은 윈도에서 HR 은?)**

| | 가슴 ECG | 손목 PPG |
| --- | --- | --- |
| **심박수** | **+21.2 bpm · 15/15명** · p=0.0001 | **+24.4 bpm · 15/15명** · p=0.0001 |

**심박수는 손목으로도 전원 일치로 잡힌다. 신호가 나쁜 게 아니다.**

**본문 — 표 3: 왜 HRV 만 안 되나**

| 지표 | ECG | PPG | 두 신호 상관 |
| --- | --- | --- | --- |
| 평균 박동 간격 | 0.8 s | 0.7 s | **r = 0.903** |
| **RMSSD** | 38.0 | **138.1 (3.6배)** | r = 0.529 |

평균은 맞는데 **변이만 3.6배 부풀려진다.** 맥파 정점이 완만해 검출 시각이 밀리초 단위로
흔들리고, RMSSD 는 *연속한 간격의 차이*를 재므로 그 지터가 그대로 들어온다.
실제 변화(−13 ms)보다 지터가 크면 신호가 묻힌다. **평균은 지터가 상쇄되어 살아남는다.**

> **한 줄** 그래서 HR 은 되고 HRV 는 안 된다. **지표의 문제가 아니라 폼팩터의 문제다.**

**말할 것** — "두 데이터에서 HRV가 안 나왔는데, 생리적으로 반응이 없는 건지
손목으로 못 재는 건지 알 수가 없었습니다. WESAD가 같은 사람에게 두 센서를 동시에 채웁니다.
가슴에서는 27% 떨어지고 손목에서는 방향이 반대입니다. 같은 윈도에서 심박수는
양쪽 다 15명 전원 올라갑니다. 결론이 하나로 나옵니다."

**각주** — `outputs/tables/` · `scripts/15_wesad_hrv.py` · `docs/HRV_VERDICT.md`

## S21. 설명이 붙어도 닫지 않는다 `C순위`

> **제목** 자기보고가 무죄 증명이 되면 안 된다
> **부제** 운동한 날에도 아플 수 있다

**본문 — 문제**

"어제 운동했다"에 체크했다고 창을 닫아버리면
**사용자의 자기보고가 곧 무죄 증명이 된다.**
그러면 **설명이 가장 잘 붙는 사람** — 매일 운동하고 자주 늦게 자는 사람 —
**이 가장 늦게 발견된다.**

**본문 — 그래서 두 가지**

| | |
| --- | --- |
| **1. 설명이 붙은 날도 지우지 않는다** | "그럴 만하다"는 조용히 넘기라는 뜻이지 없던 일로 하라는 뜻이 아니다 |
| **2. 설명으로 감당되는 크기를 넘으면 넘긴다** | 같은 사람이 평소 운동한 날 벗어나는 정도를 **학습 구간에서 미리 재두고**, 그 **상한(95분위)** 을 넘으면 닫지 않는다 |

구현: `deviation.fit_cause_ceiling()` / `EXCEEDS_EXPLANATION`
상한은 **학습 구간에서만** 정한다. 임계값과 같은 이유다 (테스트: `tests/test_deviation.py`)

> **한 줄** 설명을 받되, **설명에 상한을 둔다.**

**말할 것** — "이 슬라이드가 저희가 가장 오래 고민한 부분입니다. 사용자에게 물어보는
설계는 편한데, 잘못하면 가장 위험한 사람을 가장 늦게 찾게 됩니다."

## S22. 지속성 — 만들었고, 이 데이터로는 검증 안 된다 `C순위`

> **제목** 사흘 연속일 때만 알린다 — 검증은 아직이다
> **부제** Nurse 15명 · 관측일 236일 = 7.75 인·월

**본문 — 표 1: 공짜가 없다**

| K일 연속 | 경보/인·월 | 탐지율 |
| --- | --- | --- |
| 1 | 3.353 | 0.223 |
| 2 | **0.774** | 0.096 |
| 3 | 0.129 | 0.011 |
| 4 | 0.000 | 0.000 |

**"경보를 0.77회까지 줄였다"만 말하면 탐지율 0.096 을 숨기는 것이다.**

**본문 — 표 2: 우연 수준을 못 넘는다**

사건일이 관측일의 **39.8%** 다. 사람별 경보 개수를 유지한 채 날짜만 2,000번 섞었다.

| K | 관측 정밀도 | **우연 정밀도** | p |
| --- | --- | --- | --- |
| 1 | 0.500 | 0.612 | 0.942 |
| 2 | 0.833 | 0.635 | 0.266 |
| 3 | **1.000** | **0.576** | 0.576 |

**"정밀도 1.0"이 우연 0.576 짜리다.**

**본문 — 왜 이 데이터로는 안 되나**

이 계층은 **자는 동안** 재는 걸 전제한다. 그런데 Nurse 는 **전부 근무 중**이고,
사건이 관측일의 39.8% 로 전혀 드물지 않다.
**교란을 없애려고 새벽에 재는 설계를, 교란이 최대인 조건에서 시험한 셈이다.**

> **한 줄** 안 된다고 나온 게 아니라 **답이 아직 없는 것**이다. 그 구별은 흐리지 않는다.

**말할 것** — "여기는 안 됐습니다. 그런데 안 됐다는 것과 검증할 수 없다는 건 다릅니다.
이 계층은 자는 동안을 전제하는데 이 데이터는 전부 근무 중입니다. 조건이 반대입니다."
