## 1. 파일 구조

```
Stress_dataset.zip  (1.16 GB)
└── {참가자ID}/                    15명: 15 5C 6B 6D 7A 7E 83 8B 94 BG CE DF E4 EG F5
    └── {ID}_{epoch}.zip           총 609개 — E4 녹화 세션 하나당 zip 하나
        ├── ACC.csv  EDA.csv  BVP.csv  TEMP.csv  IBI.csv  HR.csv
        ├── tags.csv               **비어 있음** (프로토콜 태그 없음)
        └── info.txt
SurveyResults.xlsx                 시트 1개("in"), 358행
```

**세션이 개별 zip 으로 분리되어 있다.** 파일명의 epoch 가 그 세션의 시작 시각이다.
이것이 곧 `scope="subject_session"` 의 자연스러운 단위다.

## 2. 신호 포맷 — 우리 리더가 그대로 동작한다

| 신호 | 첫 행 예시 | 샘플레이트 |
| --- | --- | --- |
| BVP | `1594140175.00` | 64 Hz |
| ACC | `1594140175.000000, 1594140175.000000, 1594140175.000000` | 32 Hz |
| EDA | `1594140175.000000` | 4 Hz |
| TEMP | `1594140175.000000` | **4 Hz** |
| HR | `1594140185.000000` | 1 Hz |
| IBI | `1594140175.000000, IBI` | event |

- **타임스탬프가 epoch 실수다** (Hongn 은 날짜 문자열이었다). `io_e4.parse_time` 이
  둘 다 받으므로 수정 불필요.
- **TEMP 는 4 Hz** 다. 논문 Table 은 1 Hz 로 적었는데 실제는 4 Hz — 논문 표가 틀렸다.
- HR 시작이 BVP 보다 10초 늦다 (E4 워밍업). Hongn 과 동일하며 `slice_time` 이 처리한다.
- IBI 헤더가 `<epoch>, IBI` 형식이다. 이미 처리하는 변형이다.
- **`tags.csv` 가 비어 있다.** 구간 라벨은 `protocol.py` 가 아니라 설문에서 온다.

## 3. 라벨 — 설문 기반 사건 단위

`SurveyResults.xlsx` 단일 시트, **358행**. 각 행이 스트레스 사건 하나다.

```
ID | Start time | End time | duration | date | Stress level | (원인 13개 열) | Description
```

원인 열: COVID 관련 / 코로나 환자 치료 / 환자 위기 / 환자·가족 / 의사·동료 /
행정·검사실·약국 / 업무량 증가 / 기술 문제 / 물품 부족 / 문서작업 / 역량 /
안전 위협 / 근무환경.

### Stress level 분포 (전체 358건)

| 값 | 건수 |
| --- | --- |
| 2 (높음) | 179 |
| `na` | 113 |
| 0 (없음) | 46 |
| 1 (중간) | **20** |

**중간(1)이 20건뿐이고 `na` 가 113건이다.** 3단계 분류로 쓰기 어렵다.
0 대 2 의 이진, 또는 사건/비사건 이진이 현실적이다.

## 4. ⚠ 시간대 — 반드시 변환해야 한다

설문의 `date` + `Start time` 은 **현지 시각**이고 E4 는 **epoch(UTC)** 다.
그대로 맞추면 라벨이 통째로 어긋난다.

라벨이 실제 녹화 세션 안에 떨어지는 비율로 검정했다.

| 가정 | 세션 내부 비율 |
| --- | --- |
| UTC 그대로 | 19.6% |
| UTC−5 고정 | 74.0% |
| UTC−6 고정 | 75.7% |
| **America/Chicago (DST 반영)** | **78.5%** |

연구 기관이 University of Louisiana at Lafayette 이므로 미국 중부시간이 맞다.
4월~12월이라 서머타임 경계를 넘으므로 **고정 오프셋이 아니라 `America/Chicago`
타임존을 써야 한다.**

남은 21.5% 는 밴드를 착용하지 않은 시간에 일어난 사건이거나, 이 검정에서 세션
길이를 3시간으로 근사한 탓이다. 실제 세션 길이로 다시 재야 한다.

### 매칭된 라벨 (281건)

| 항목 | 값 |
| --- | --- |
| 세션에 매칭된 사건 | 281 / 358 (78.5%) |
| 수준별 | 2:141 / `na`:91 / 0:34 / 1:15 |
| 사건 길이 | 중앙값 16분, 합계 110시간 |
| 참가자 | 15명 전원이 세션과 매칭 사건을 모두 가짐 |

## 5. Hongn 대비

| | Hongn | Nurse |
| --- | --- | --- |
| 환경 | 실험실 | **실제 병원 근무** |
| 착용 세션 | 100 (1인당 3) | **609 (1인당 9–90)** |
| "평소" | 자극 전 3분 = 윈도 1개 | **세션마다 수 시간** |
| 라벨 | 프로토콜 전 구간 | 사건 단위, 110시간만 |
| 운동 라벨 | 있음 (자전거) | **없음** (다만 간호사는 계속 걷는다) |
| 타임스탬프 | 날짜 문자열 | epoch 실수 |

**개인 baseline 문제가 여기서 해결된다.** 앞서 측정한 요구조건(착용 1회당 안정
구간 8개 이상)을 세션마다 충분히 만족한다.

## 6. 이 데이터가 우리 연구 질문에 맞는 이유

간호사는 근무 중 **계속 걷는다.** 즉 "심박이 올랐는데 걸어서인가 환자 위기 때문인가"
가 실제로 발생하는 상황이다. 우리 파이프라인이 그대로 대응한다.

```
개인 baseline 이탈 감지 (세션 단위)
        ↓
활동으로 설명되나? (ACC — 병동 이동)
        ↓  아니오
설명 안 되는 이탈
        ↓
설문에 보고된 스트레스 사건 시각과 대조
```

**주의.** 라벨이 사건 단위이고 1,250시간 중 110시간만 덮는다.
**라벨 없음이 스트레스 없음을 뜻하지 않는다.** 따라서
"설명 안 되는 이탈"을 오탐으로 세면 안 되고, 보고된 사건과의 **일치율**로만
평가해야 한다.
