## 로더 (`src/nesy/mishra.py`)

출력은 `homekit.build_day_table()` 이 받는 (day, night) 두 표다. 기준선·설명·보류·상한은
Homekit 것을 그대로 쓴다.

| 결정 | 이유 |
| --- | --- |
| 밤 심박 = 0~6시, **앞선 12분 걸음 0** 인 분의 평균 | 수면 단계가 32명에게만 있다. Mishra 의 RHR 정의를 따른다 |
| 걸음 기록이 없는 분은 0 으로 보지 않는다 | 미착용을 '가만히 있음' 으로 세면 안 된다 |
| 고강도 활동 = 분당 100보 이상 | Fitbit 고강도 기준의 근사 |
| COVID 사건일 = 진단 전 30일 안의 **마지막** 증상일 | 표 3 에는 다른 시기 증상 에피소드도 섞여 있다 |
| 설명 상한은 사람 단위 5-fold 로 정한다 | 32건으로 train/test 를 나누면 test 가 10건 안팎밖에 안 남는다 |

## 결과 (2026-10-03, z ≥ 2, 경보 창 = 증상 7일 전 ~ 3일 후)

유효일: COVID 30명 2,576일 · 건강 63명 3,179일 · 기타 11명 535일.

**이탈일 564일 중 운동·수면으로 설명된 날은 91일(16%) 뿐이다.**

| K | 조건 | 건강군 경보/인·월 | COVID 탐지 |
| --- | --- | --- | --- |
| 1 | raw | 1.35 | 20/32 (0.63) |
| 1 | ours | 1.28 | 19/32 (0.59) |
| 2 | raw | 0.36 | 10/32 (0.31) |
| 2 | ours | 0.34 | 9/32 (0.28) |
| 2 | ours (수면 설명 뺌) | 0.34 | 10/32 (0.31) |
| 3 | raw | 0.11 | 6/32 (0.19) |
| 3 | ours | 0.10 | 5/32 (0.16) |

**경보 수를 맞추면 ours 와 raw 의 탐지율이 같다** (K=1·2 동일, K=3 에서 1건 차이).
즉 이 데이터에서 **설명 계층은 아직 일을 하지 않는다.**

참고로 논문의 경보 빈도(표 29, 30일당)는 건강군 0.62 · COVID 0.70 · 기타 0.70 이다.
우리 K=2 건강군 0.34 는 정의가 달라 직접 비교는 안 된다.

### 해석

1. **걸음과 수면만으로는 '평소와 다른 날' 의 대부분을 설명하지 못한다.** README 가 말한
   "월 15회" 의 원인 — 음주, 스트레스, 늦게 잔 날 — 은 이 데이터에 기록이 없다.
   설명 계층이 일하려면 **그 맥락을 기록한 데이터**가 필요하다 → PMData (음주·스트레스 일지).
2. **수면 부족은 감염의 결과일 수 있다.** COVID 환자 APGIB2T 의 증상 기간 이탈일이
   '수면 부족' 으로 닫혔다. 운동과 달리 수면은 원인이자 증상이다. 수면 설명을 빼면
   K=2·3 에서 놓친 1건이 돌아온다. 설명 규칙마다 **인과 방향**을 따져야 한다.
3. 사건이 32건이라 탐지 1건 = 0.031 이다. 위 차이는 모두 1건 수준이며 유의하지 않다.
