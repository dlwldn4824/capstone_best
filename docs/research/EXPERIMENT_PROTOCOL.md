# 자체 실험 프로토콜 — 상용 스트레스 점수 역설계

Spang et al. 2022, *Reconstruction and Physiological Basis of Samsung's Galaxy
Watch Stress Score* (HCI International) 의 설계를 따라, 우리 규모로 재현한다.

**연구 질문**

1. 갤럭시 워치 스트레스 점수는 실제로 **무엇을 보고** 만들어지는가
2. 손목 PPG 로 잰 HRV 는 가슴 ECG 대비 **얼마나 부정확한가**
3. 상용 점수는 **주관적 스트레스**와 얼마나 맞는가

2번이 핵심이다. 우리는 두 공개 데이터에서 "HRV 가 스트레스를 반영하지 않는다"를
확인했는데, 그것이 **생리 현상인지 측정 한계인지** 아직 가르지 못했다.
같은 사람 같은 시각에 ECG 와 손목 PPG 를 동시에 재면 그 답이 나온다.

---

## 1. 준비물

| 항목 | 비고 |
| --- | --- |
| Galaxy Watch (4 이상) | 스트레스 점수 기능 필요. 1–2대 있으면 회전 운용 |
| **Polar H10** 가슴 스트랩 | 10만 원대. ECG·RR 기준 측정 |
| 안드로이드 폰 | `Polar Sensor Logger` (무료) 설치 |
| 노트북 | 구간 타임스탬프 기록 |
| 자기보고 용지 | 구간마다 1–10 |

### 데이터 경로

- **워치** → Samsung Health → 설정 → 개인 데이터 다운로드 → CSV + JSON
  (연속 스트레스, HRV(SDNN/RMSSD) 포함. 상세값은 `jsons/` 의 `binning_data`)
- **Polar** → Polar Sensor Logger → HR / RR / ECG / ACC 파일 저장 → PC 전송

> ⚠ **첫 참가자 전에 반드시 한 번 예행하고 실제 export 를 열어볼 것.**
> 스트레스 점수 간격이 분 단위가 아니라 10분 단위 이상이면 프로토콜 구간을
> 그에 맞춰 늘려야 한다. 이것을 확인하지 않고 15명을 돌리면 전부 버린다.

---

## 2. ⚠ 시각 동기화 — 가장 중요한 절차

Nurse 데이터에서 설문 시각과 신호 시각이 어긋나 라벨의 21% 를 잃었다.
같은 실수를 반복하지 않는다.

**시작 전**

1. 폰·노트북·워치의 **자동 시각 설정을 모두 켠다** (NTP 동기)
2. **워치 화면과 노트북 시계를 한 장에 담아 사진을 찍는다** ← 오프셋 증거
3. 사진 파일명에 참가자 ID 를 넣어 보관

**종료 후**

4. 같은 사진을 한 번 더 찍는다 (드리프트 확인)

시계가 어긋나 있어도 이 두 장으로 사후 보정이 가능하다.
**사진이 없으면 보정이 불가능하다.**

## 3. 프로토콜 (참가자당 약 30분)

Hongn v2 를 압축하되 **baseline 을 늘렸다.** Hongn 은 자극 전 안정 구간이
3분뿐이라 개인 기준을 만들 윈도가 1개밖에 나오지 않았다. 우리 실측에서
**참조 윈도 8개(약 8분)** 부터 이탈 탐지가 포화했으므로 8분을 잡는다.

| # | 구간 | 시간 | 라벨 |
| --- | --- | --- | --- |
| 0 | 착용·적응 | 3분 | (제외) |
| **1** | **안정 baseline** | **8분** | REST |
| 2 | 암산 + 소음 (5초 제한) | 3분 | STRESS |
| 3 | 회복 | 5분 | REST |
| 4 | 찬반 토론 (찬성 1분 → 반대 1분) | 2분 | STRESS |
| 5 | 회복 | 5분 | REST |
| 6 | 1022 에서 13씩 빼기 (구두) | 2분 | STRESS |
| 7 | 종료 안정 | 3분 | REST |

**총 31분** (적응 포함)

### 각 구간 전후

- 자기보고 스트레스 **1–10** 을 구두로 받아 기록
- 구간 시작·종료 시각을 **노트북에서 버튼으로 기록** (tags 역할)

### 진행 스크립트 (요약)

```
1  "편하게 앉아 계세요. 8분 동안 아무것도 안 하셔도 됩니다."
2  "화면의 뺄셈을 5초 안에 답해주세요. 틀리면 처음부터입니다." (소음 재생)
3  "쉬세요."
4  "○○에 대해 찬성 입장에서 1분간 말해주세요." → "이번엔 반대 입장으로요."
5  "쉬세요."
6  "1022에서 13씩 빼면서 소리 내어 말해주세요. 틀리면 다시 시작합니다."
7  "끝났습니다. 3분만 더 앉아 계세요."
```

## 4. 참가자

| | |
| --- | --- |
| 목표 | **15–20명** (Spang et al. 은 45명) |
| 소요 | 1인당 40분 (준비·정리 포함) |
| 기간 | 팀 3명이 나눠 진행하면 2–3주 |
| 기록 | 나이, 성별, 카페인 섭취, 수면 시간, 운동 여부 |

**동의**: 생체신호 수집과 익명 분석에 대한 서면 동의를 받는다.
학과 IRB 요건을 미리 확인할 것.

### 일별 컨디션 1문항 — 지속성 계층 검증에 이것만 있으면 된다

30분 프로토콜과 **별개로**, 참가자에게 30일간 매일 아침 한 문항만 받는다.

```
어제 컨디션이 평소와 달랐나요?
  □ 평소와 같음
  □ 달랐음 → 짚이는 이유:  □운동 □음주 □수면부족 □업무 □몸살·감기 □모르겠음
```

**소요 10초.** 밴드를 야간에 계속 차고 이 한 줄만 받으면
`persistence.py` 가 필요로 하는 세 가지가 전부 채워진다.

| 필요 | 이 항목이 주는 것 |
| --- | --- |
| 야간 연속 착용 30일 이상 | 착용 기간 그대로 |
| **드문** 사건 라벨 | "몸살·감기" 는 월 0.2회 수준 — Nurse(39.8%)와 달리 진짜로 드물다 |
| 설명 요인 | 나머지 체크박스가 곧 소거 대상 |

Nurse 로 지속성 계층을 검증하지 못한 이유가 정확히 이 세 가지의 부재다
([`PERSISTENCE.md`](PERSISTENCE.md) 4절). **30일 야간 착용 + 1문항이
30분 프로토콜보다 이 연구에 더 중요할 수 있다.**

## 5. 분석 계획

### 5.1 대리 모델 — 삼성은 무엇을 보는가

우리 51개 feature 로 삼성 스트레스 점수를 **회귀**한다.
`baseline_ml.feature_importance()` 를 그대로 쓴다.

```
입력  우리 feature 51개 (Polar ECG 기반 + 워치 PPG 기반 각각)
출력  삼성 스트레스 점수
모델  XGBoost 회귀, 피험자 분리 교차검증
```

**feature importance 가 곧 "삼성이 뭘 보고 있나" 이다.**
Spang et al. 은 **심박수(bpm)가 지배적**이라고 보고했다. 재현되는지 본다.

### 5.2 손목 HRV vs 가슴 ECG HRV ← 핵심

같은 구간에서 두 방식으로 RMSSD·SDNN 을 계산해 비교한다.

| 확인할 것 | 의미 |
| --- | --- |
| 두 HRV 의 상관 | 손목 PPG HRV 가 얼마나 믿을 만한가 |
| ECG HRV 는 스트레스에 반응하는가 | 반응하면 **측정 한계**, 안 하면 **생리적 사실** |
| 손목 HRV 는 반응하는가 | 우리 공개 데이터 결과의 재현 |

**이 표 하나가 우리 논문의 빈 구멍을 메운다.**

### 5.3 삼성 점수 ↔ 주관 보고

구간별 자기보고와 삼성 점수의 상관. 피험자 내 짝지은 비교.

### 5.4 우리 구조와의 비교

같은 데이터에 우리 이탈 점수 + 소거 구조를 적용해
삼성 점수와 나란히 놓는다.

## 7. 실패 지점 체크리스트

붙이기 전에 하나씩 확인한다. 전부 우리가 이미 한 번씩 밟은 것들이다.

- [ ] **일별 1문항을 30분 프로토콜보다 먼저 시작한다** — 30일이 걸리므로
      가장 긴 선행 작업이다. 여기서 밀리면 지속성 계층은 또 검증 못 한다
- [ ] **스트레스 점수 간격 확인** — 10분 단위면 프로토콜을 늘려야 한다
- [ ] **시각 동기 사진** — 없으면 사후 보정 불가
- [ ] **타임존** — export 가 현지 시각인지 UTC 인지 확인 (Nurse 에서 21% 손실)
- [ ] **Polar 접촉** — 전극에 물을 묻힌다. 마르면 RR 이 튄다
- [ ] **워치 착용 위치** — 손목뼈 위 2cm, 조이게. 느슨하면 PPG 가 무너진다
- [ ] **첫 1명은 버릴 각오로** 예행한다
- [ ] 참가자 ID 는 익명 코드로. 이름을 파일명에 넣지 않는다
