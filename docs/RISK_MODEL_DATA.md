# 위험 알람 모델 — 정확히 어떤 데이터가 있어야 하나

지금 웹앱의 "사흘째 알림"은 **학습된 모델이 아니라 규칙 + 잠정 임계값**이다
(`webapp/engine.py`). "위험 알람 모델"로 부르려면 아래 세 가지가 **같은 사람, 같은 날짜**로 묶인 데이터가 필요하다.

## 1. 필요한 데이터 세 덩어리

| 덩어리 | 무엇 | 왜 |
| --- | --- | --- |
| **A. 몸 신호** (매일, 몇 주 이상) | 잠든 동안 심박 · 수면 시간 · 걸음/고강도 활동 · (있으면) 피부 온도 · 밤 호흡수 · 피부전도 | 개인 기준선과 이탈을 만든다 |
| **B. 생활 맥락** (매일) | 음주 · 늦잠/짧은 잠 · 운동 · 긴장 · **생리 주기** · 약 · 시차 | 설명되는 이탈을 걷어낸다. 생리 주기는 밤 심박·체온을 바꾸는데 지금 빠져 있다 |
| **C. 결과 라벨** (날짜 포함) | **아프기 시작한 날** · 검사/진단 결과 · 진료 여부 · 아프지 않았다는 확인 | 알람이 맞았는지 채점한다. 이게 없으면 모델이 아니라 규칙이다 |

### 하루 한 줄 스키마 (서비스가 쌓아야 할 것)

```
subject_id, day,
night_hr, night_min, asleep_min, very_active_min, steps,
skin_temp_dev, resp_rate, eda_tonic,              # 기기에 있으면
alcohol, short_sleep, exercise, tense, menstrual_phase, meds,   # 맥락
symptoms[...], face_hr, face_a,                   # 아침 체크
outcome_onset, outcome_test, outcome_visit        # 나중에 채워지는 결과
```

## 2. 얼마나 있어야 하나 — 사건 수가 전부다

탐지율의 95% 신뢰구간 폭 (탐지율 0.5 가정):

| 아픈 사건 수 | 신뢰구간 | 예 |
| --- | --- | --- |
| 32 | ±0.17 | Mishra 2020 (COVID) — 지금 우리가 가진 최대 |
| 100 | ±0.10 | 모델 비교가 겨우 되는 수준 |
| 400 | ±0.05 | 임계값을 믿고 정할 수 있는 수준 |

성인은 감염이 한 달에 0.2번 안팎이므로 **사건 100개 ≈ 500 인·월** (예: 100명 × 5개월).
팀원 2–3명이 2주 차는 것으로는 **아픈 사건이 0개**다. 자체 수집으로 모델을 학습할 수는 없다.

## 3. 지금 손에 있는 / 얻을 수 있는 데이터

| 데이터 | A 신호 | B 맥락 | C 결과 | 접근 |
| --- | --- | --- | --- | --- |
| Hongn 2025 | 실험실 E4 (피부전도 O) | 운동·스트레스 (실험) | ✕ | 보유 |
| Nurse 2022 | 근무 중 E4 (수면 ✕) | 스트레스 자기보고 | ✕ | 보유 |
| WESAD | 가슴 ECG + 손목 | 실험 | ✕ | 보유 |
| **Mishra 2020** | 심박·걸음 (수면 32명) | ✕ | **COVID 32 · 기타 질병 15** | 보유 (공개) |
| **PMData** | 심박·수면·활동 | **음주·스트레스 매일** | ✕ | 보유 (공개) |
| **Homekit2020** | 심박·수면·걸음 (분) | 증상 매일 | **PCR 독감** | 신청 (기관 신원 확인서) |
| 자체 수집 (Watch8) | 심박·**피부전도·체온** | 앱 4탭 | ✕ (2주엔 사건 없음) | 예산 안 |

**세 덩어리를 다 가진 데이터는 하나도 없다.** 그래서 모델을 한 덩어리로 학습하지 않고,
**모듈마다 그 라벨을 가진 데이터로** 맞춘다.

## 4. 모듈별로 무엇으로 맞추나

| 모듈 | 하는 일 | 맞추는 데이터 | 상태 |
| --- | --- | --- | --- |
| 기준선·이탈 | 밤 심박이 평소와 얼마나 다른가 | Mishra · Homekit (아픈 날 vs 아닌 날) | Mishra 로 확인함 |
| 설명 | 어떤 원인이 얼마나 올리나 · 상한 | **PMData** (음주 +2.6 bpm, 12/13명) · Hongn (운동·피부전도) | 효과 크기 확인함, 상한은 잠정값 |
| 누적·알람 임계 | 며칠·얼마면 알릴까 | Mishra (+ Homekit) — 건강군 경보율 vs 탐지율 | Mishra 로 확인함 (차이 없음) |
| 증상 → 진료 안내 | 지금 증상으로 급한 정도 | 문헌·진료지침 (데이터 학습 아님) | 의료진 검토 필요 |
| 얼굴 | 얼굴 심박 정확도 | MCD-rPPG · UBFC · Polar H10 | **질병 라벨 없음 → 알람 판단에 넣지 않는다** |
| 피부 온도 | 발열 전 상승 | **공개 데이터 없음** (Oura·WHOOP 비공개) | 자체 수집으로 '측정'만 |

## 5. 모델 단계

1. **지금 — 규칙 (설명 가능한 기준선)**: 이탈 z ≥ 2, 설명 상한, 3일 누적. 임계값을 Mishra·PMData 로 맞춘다.
2. **Homekit 승인 후 — 작은 학습 모델**: 하루 단위 특징
   (`night_z, run_len, explained_frac, 맥락 플래그, 증상 플래그`) → 로지스틱 회귀로
   "3일 안에 아프기 시작할 확률". 사람 단위 교차검증, 확률 보정,
   **건강군 경보율 ≤ 0.5회/인·월**에서 탐지율이 가장 높은 임계값을 고른다.
   계수가 그대로 읽히므로 규칙 기반 설명(NeSy)과 이야기가 이어진다.
3. **서비스 운영 중 — 스스로 라벨을 모은다** (아래 6번).

## 6. 서비스에 연결하는 법

이미 연결 지점이 있다: `webapp/engine.py` 의 `compute()` 가 하루 표를 만들고 상태를 낸다.

```
하루 표 (engine._frame)
  → 특징 (night_z, run_len, 설명된 몫, 맥락, 증상, 얼굴)
  → risk_model.predict()  ← 1단계: 지금 규칙 / 2단계: 학습 모델 (같은 자리에 끼운다)
  → 위험도 0–3
  → 화면: 평소 / 남았어요(지켜봄) / 증상 확인 권유(팝업) / 진료 권유
```

그리고 **알람마다 나중에 결과를 묻는다** — 서비스가 C 덩어리를 스스로 만든다.

| 언제 | 묻는 것 | 쌓이는 라벨 |
| --- | --- | --- |
| 알람 직후 | 증상 고르기 (이미 있음) | 증상 |
| 3일 뒤 | "그때 아팠나요?" 예 / 아니오 / 이유가 있었어요 | 맞은 알람 / 헛알람 / 놓친 설명 |
| 7일 뒤 | "진료를 받았나요? 진단은?" (감기 · 독감 · 코로나 · 기타 · 안 받음) | 진단 라벨 |
| 알람 없던 날 | 주 1회 "이번 주 아팠던 날이 있었나요?" | **놓친 사건** (탐지율 분모) |

알람 없던 주에도 물어야 탐지율을 잴 수 있다. 알람 난 날만 물으면 정밀도만 알고 탐지율은 모른다.

## 7. 정리 — 지금 말할 수 있는 것

- **지금 데이터로 할 수 있는 것**: 규칙 기반 알람을 공개 데이터로 맞추고, 그 한계를 숫자로 보이는 것 (Mishra: 경보 수를 맞추면 차이 없음 / PMData: 음주는 진짜 설명).
- **학습된 위험 모델**: Homekit 승인이 있어야 시작할 수 있다 (PCR 라벨 + 매일 증상).
- **얼굴·체온**: 측정은 되지만 질병과 연결된 공개 데이터가 없다. 알람 판단에서 빼고 '참고 정보'로 둔다.
- **장기적으로**: 서비스가 6번의 질문으로 결과 라벨을 스스로 모으는 것이 유일하게 확장 가능한 길이다. 이 데이터는 개인 건강 정보이므로 **IRB와 동의서**가 먼저다.
