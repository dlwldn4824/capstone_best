# 거울 기록 — 기획 변경 보고서(2026-10-19) 적용

보고서: 「캡스톤 기획 변경 보고서: 설명되는 변화와 설명되지 않는 변화의 기록」 (@이교원, Team 삼삼오오)

워치 없이 **전면 카메라 하나**로, 아침 거울 · 공부 시작 · 밤 세안 때 15초씩 얼굴 심박과 안색을 기록하고,
평소와 다르면 이유를 한 번 묻고, 시험기간 리포트로 정리한다.

```bash
python webapp/fetch_vendor.py          # 얼굴 메시(MediaPipe) 로컬에 받기 — 한 번만 (없으면 CDN)
python webapp/server.py --https        # 폰(아이폰 Safari 포함)에서 카메라를 쓰려면 https
```

`/` 가 거울 기록이다. 워치 버전(`/v1` 폰 · `/watch`)은 `legacy/webapp_v1/` 에 보관만 하고 서버가 내보내지 않는다.

## 보고서와 다른 점 (의도한 것)

| 보고서 | 여기 | 이유 |
| --- | --- | --- |
| iOS 앱 · ARKit 얼굴 메시 1,220점 | 웹앱 · **MediaPipe Face Landmarker** 478점 | 이 개발 환경(Windows)에서 iOS 빌드 불가. 같은 역할: 메시 + 표정 계수 52종(ARKit 과 같은 이름) + 머리 자세. 아이폰 Safari 에서도 돈다 |
| SwiftData 기기 내 저장 · 서버 없음 | 같은 기기에서 도는 로컬 서버 + SQLite | 영상 · 메시 · 픽셀은 **브라우저 밖으로 나오지 않는다.** 서버가 받는 것은 숫자뿐 (7.4 저장 정책 그대로) |
| 대역 통과 0.7–4 Hz | 0.75–3 Hz → 0.6–3.3 Hz | rPPG-Toolbox 처리 순서를 그대로 따랐다 (아래 검증) |
| AI 가 리포트 문장 작성 | 규칙으로 문장 생성 (`report_sentences`) | 입력은 이미 '수치 요약만'. LLM 으로 바꿀 자리와 입력 형식을 고정해 뒀다 |

| | v1 (이전 앱) | **v2 (지금)** |
| --- | --- | --- |
| 평균 오차 | 12.5 bpm | **3.6 bpm** (원 논문 POS 3.80) |

| 통과한 창의 오차 | 3.1 bpm (94%) | **0.7 bpm (96%)** |

rPPG-Toolbox 는 Responsible AI License 라 코드를 옮기지 않고 같은 단계 · 같은 값으로 새로 썼다.

### 안색: 이마 대비 상대값 — 60명 · 20초 구간 961개

| 지표 | 같은 영상 안 흔들림 | 밝기 추종 ρ | 운동 전후 변화 / 잡음 |
| --- | --- | --- | --- |
| 볼 a\* 절대값 | 1.57 | −0.16 | 0.77 |
| **볼 a\* − 이마 a\*** | **0.63** | 0.08 | 1.19 |

상대값이 측정 잡음을 **2.5배** 줄이고 밝기 추종을 절반으로 줄인다 — 보고서 8.4 의 판단이 맞다.
하지만 운동 후 붉어짐의 **방향은 일관되지 않았다** (52%, p=0.30). 음주 붉어짐은 공개 데이터가 없어
보고서 10장대로 **음주 전후 자기 촬영**으로 정해야 한다. 그때까지 안색은 판정을 바꾸지 않는 보조 신호다.
